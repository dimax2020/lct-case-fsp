# Адаптивный тест на грейд

Тест определяет грейд кандидата в выбранной специализации и даёт категорию «специализация × грейд», которую видит работодатель. Он заменяет фиксированный набор заданий из MVP (`MVP_TZ.md`, п. 8 «Тест не адаптивный») на адаптивный тест (CAT) по модели IRT 2PL. Источник механики и банка — `tmp_bank/README.md` и `tmp_bank/bank.json`.

Коротко: каждое следующее задание подбирается под текущую оценку уровня кандидата. Поэтому 8–20 заданий дают ту же точность, что длинный фиксированный тест. У двух кандидатов почти не совпадает набор заданий, а слив части банка почти не помогает.

## Место в продукте

- Тест **обязательный**: без него у кандидата нет категории и места в рейтинге.
- Путь кандидата: «Тесты и грейд» → `/candidate/onboarding` (опрос → тест → результат). Итоги и пересдачи — на `/candidate/grade`.
- Результат записывается в профиль: грейд, балл 0–100, место в категории, баллы по навыкам с `source = test`. Подбор читает только профиль и ничего не знает об устройстве теста.
- В прототипе доступны **Backend и Frontend**. Остальные специализации в опросе скрыты, API отвечает `400 specialization_unavailable`.

## Сценарий кандидата

1. **Опрос:** до трёх отраслей, специализация, заявленный грейд (Intern…Lead). «Начать тест» активна, когда выбраны все три поля.
2. **Тест:** одно задание на экране. Можно ответить, пропустить или завершить досрочно. Прогресс сохраняется на сервере, поэтому можно уйти и вернуться позже: незавершённая попытка подхватывается автоматически.
3. **Остановка:** тест заканчивается сам, когда оценка достаточно точна (см. «Алгоритм»), или при досрочном завершении.
4. **Результат:** категория, решение по грейду, θ, SE, процентиль, измеренный грейд. Дальше — тест рабочего стиля (`PSYCH_TEST.md`) или страница грейда.

## Банк заданий

Задание — конкретный вариант (`tmp_bank/instances.json`) поверх шаблона из `bank.json`. Шаблон даёт параметры IRT, грейд, теги и время, вариант — текст, код, варианты ответа и ключ. В прототипе 60 вручную проверенных вариантов, по 30 на специализацию:

| | Backend | Frontend |
|---|---|---|
| Junior / Middle / Senior | 10 / 10 / 10 | 10 / 10 / 10 |
| MCQ — один вариант | 15 | 15 |
| MSQ — несколько вариантов | 3 | 2 |
| SHORT — короткий ответ | 1 | 2 |
| DEBUG — найти ошибку (выбор из вариантов) | 2 | 2 |
| CODE — написать код | 5 (Python, SQL) | 5 (JavaScript, TypeScript) |
| REVIEW — код-ревью | 2 | 2 |
| CASE — проектный кейс | 2 | 2 |
| Различительная способность `a` | 0,8–1,5 | 0,9–1,5 |
| Сложность `b` | −1,8…1,9 | −1,5…1,8 |

Правила банка, которые проверяет `tests/test_cat.py`:

- в тексте нет незаполненных параметров шаблона;
- у вопросов с выбором есть не меньше двух вариантов и правильный ответ;
- у каждого задания есть способ проверки (ключ вариантов, список допустимых ответов или рубрика);
- в каждой специализации не меньше 30 заданий.

Если банк обновили посреди попытки и текущего задания больше нет, попытка не ломается: сервер подбирает замену.

## Алгоритм

**Модель.** Вероятность решить задание: P(θ) = 1 / (1 + e^(−1,7·a·(θ − b))), где θ — уровень кандидата, a — различительная способность задания, b — сложность.

**Оценка уровня (EAP).** Апостериорное распределение θ считается на сетке из 161 точки от −4 до 4 с априорным N(0, 1). После каждого ответа θ — среднее распределения, SE — его стандартное отклонение. Задание считается решённым при балле ≥ 0,75, поэтому частичный балл 0,5 за кейс в оценке θ идёт как «не решено» (полный балл сохраняется для навыков).

**Старт.** Первое задание подбирается около уровня заявленного грейда: Intern −2,2, Junior −1,8, Middle −0,5, Senior 0,7, Lead 1,8 (стартовая точка смешивается с N(0, 1)).

**Выбор задания.**
1. Из ещё не показанных заданий берутся пять самых информативных при текущей θ (информация Фишера (1,7a)²·P·(1 − P)).
2. Из этих пяти одно выбирается случайно; генератор привязан к попытке.
3. **Ограничение экспозиции:** после 50 завершённых тестов задание, показанное больше чем в 25 % тестов, временно исключается. Это защищает банк от заучивания.

**Остановка.**
- Не раньше 8 заданий: тест заканчивается, когда SE < 0,30, или на 20-м задании.
- **Пограничная зона:** если в момент остановки θ ближе к порогу грейда, чем SE, тест продлевается до 5 заданий, нацеленных на этот порог. Продление заканчивается, когда θ выходит из зоны или задания исчерпаны; всего не больше 25 заданий.
- **Досрочное завершение:** результат считается по уже данным ответам; без ответов — по стартовой оценке.

## Проверка ответов

| Формат | Как считается балл (0…1) |
|---|---|
| MCQ, DEBUG | 1, если выбран правильный вариант, иначе 0 |
| MSQ | (верно отмеченные − лишние) / число верных, не меньше 0 |
| SHORT | 1, если ответ совпал с одним из допустимых. Сравнение без учёта регистра, ё/е, кавычек, пробелов и знаков препинания; для числовых ответов — по первому числу в ответе |
| CODE, REVIEW, CASE | Рубрика: группы ключевых элементов с синонимами (`keys`). Балл = найденные группы / требуемое число (`need`), не больше 1 |
| Пропуск | 0 |

Эталонное решение каждого кодового задания проходит рубрику на 1,0, отписка вроде «не знаю» получает 0 — это тоже покрыто тестами. Запуск кода в песочнице (Piston) для CAT-заданий не используется: у вариантов банка пока нет автотестов.

## Результат

**Измеренный грейд** — по порогам θ:

| θ | < −1,2 | −1,2…0,2 | 0,2…1,2 | 1,2…2,2 | ≥ 2,2 |
|---|---|---|---|---|---|
| Грейд | Intern | Junior | Middle | Senior | Lead |

**Решение:**

| Решение | Условие | Сообщение кандидату |
|---|---|---|
| Пограничная зона | \|θ − ближайший порог\| < SE | Заявлен X, оценка Y, категория Z |
| Уверенно выше | Измеренный выше заявленного | Можно пройти тест на грейд выше |
| Ниже заявленного | Измеренный ниже заявленного | Принудительного понижения нет, можно пройти тест на грейд ниже |
| Подтверждён | Совпали | Грейд подтверждён |

**Какой грейд присваивается:**

- первый тест в специализации — измеренный;
- повторный тест — текущий грейд сохраняется, понижения нет;
- тест на соседний грейд (кнопки «Пройти на грейд выше/ниже») — заявленный, если измеренный не ниже заявленного, иначе текущий сохраняется;
- грейд другой специализации не переносится: при смене Backend → Frontend первый тест снова считается первым.

Пометка «готов к следующему» ставится, если измеренный грейд выше присвоенного.

**Числа в профиле:**

- балл 0–100 = (θ + 3) · 100 / 6;
- процентиль — оценка по нормальной шкале θ;
- место в категории — ранг по баллу среди кандидатов той же специализации и грейда.

**Баллы по навыкам** — доля верных ответов в заданиях последнего теста, где проверялся навык. Мелкие теги банка (около 45 на специализацию) сводятся к навыкам таксономии, чтобы балл опирался на несколько заданий и совпадал с навыками вакансий:

| Backend | Frontend |
|---|---|
| Python, SQL, PostgreSQL, HTTP и API, Git, Алгоритмы, Проектирование систем, Безопасность, Отладка и ревью кода | JavaScript, TypeScript, React, CSS и вёрстка, HTML/формы/доступность, Браузер и производительность, Архитектура фронтенда, Безопасность, Отладка и ревью кода |

## Правила попыток и таймер

- Одна активная попытка. Повторный старт возвращает её же.
- Повтор на тот же грейд — через 30 дней, смена грейда — раз в 90 дней. В демо-стенде правила выключены флагом `ASSESSMENT_COOLDOWN=off`, на страницах показан их рабочий срок.
- Лимит — 90 минут на тест. В прототипе таймер выключен (`ASSESSMENT_TIMER=off`): в интерфейсе указано, что таймер будет и на сколько, но время не идёт. С включённым таймером по истечении срока тест завершается по данным ответам.

## Интерфейс теста

- Ввод под формат:
  - карточки вариантов с буквами — один или несколько ответов;
  - однострочное поле — короткий ответ;
  - моноширинное поле с отступом по Tab — код;
  - большое поле — ревью и кейс.
- Код к заданию выводится отдельным блоком под условием, в поле ответа есть подсказка формата.
- «Ответить» неактивна, пока ответа нет. Клавиши: 1–9 выбирают вариант, Enter отправляет ответ, в поле кода и в развёрнутом ответе — Ctrl/⌘+Enter.
- Прогресс-бар с отметкой минимума в 8 заданий. Текущая оценка во время теста не показывается, чтобы не влиять на ответы.
- «Завершить досрочно» — со второго нажатия, с предупреждением, по скольким ответам будет посчитан результат.

## Что получает работодатель и подбор

- Категория, грейд, балл, место в категории и дата теста — в карточке кандидата и выдаче.
- Навыки с `source = test`. В матчинге покрытие обязательного навыка = балл / 100 (`MVP_TZ.md`, `must_cov`).
- **Чертёж под вакансию** (`GET /assessment/blueprint?need_id=…`): какие темы и примеры заданий банка ближе всего к навыкам потребности.
- **Микрозадания** из банка на странице грейда обновляют свежесть профиля.

## API

Префикс `/api/v1/assessment`.

| Метод | Назначение |
|---|---|
| `GET /eligibility` | Можно ли начать; активная попытка; даты следующих попыток |
| `POST /attempts` `{specialization, declared_grade}` | Начать тест или вернуть активную попытку |
| `GET /attempts/{id}` | Состояние: текущее задание без ключа, прогресс, таймер, результат |
| `POST /attempts/{id}/answers` `{task_id, answer \| code + language \| skip}` | Ответ на текущее задание; в ответе — следующее задание или результат |
| `POST /attempts/{id}/finish` | Досрочное завершение |
| `POST /retake` `{direction: up \| down}` | Тест на соседний грейд |
| `GET /micro-tasks`, `POST /micro-tasks/{id}/answer` | Микрозадания |

Ответить можно только на текущее задание: другое — `404`; ответить после завершения нельзя — `409`. Ключи ответов клиенту не отдаются.

## Качество

- `tests/test_cat.py` проверяет:
  - EAP и пороги грейдов;
  - выбор задания с экспозицией;
  - правила решения по грейду;
  - корректность банка;
  - проверку каждого формата ответа;
  - покрытие навыков: все теги сведены, почти каждый навык опирается не меньше чем на два задания.
- `tests/test_cat_api.py` — сквозной сценарий через API.
- Симуляция `tmp_bank/sim.py` на полном банке шаблонов: 2000 синтетических кандидатов на специализацию, каждый проходит тест дважды:

  | Метрика | Значение |
  |---|---|
  | Точность грейда | 84–86 % |
  | Ошибка больше чем на один грейд | 0 % |
  | Тот же грейд при повторе вне пограничной зоны | 87–91 % |
  | Корреляция оценки с истинным уровнем | 0,96–0,97 |
  | Максимальная экспозиция | 0,25 |
  | Сдвиг оценки при утечке 20 % банка | ≤ 0,10 |
