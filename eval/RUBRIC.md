## Релевантность кандидата потребности (0–3)

Проверяются уровни сверху вниз. Сработал более высокий — нижние не смотрят.

Общие слова:

- дистанция грейда — до ближайшего грейда потребности по шкале intern < junior < middle < senior < lead;
- навык «есть», если у кандидата есть строка с этим `skill_id` и любым `source`;
- формат совместим, если пересечение списков форматов непустое;
- домен допустим, если его нет в `blocked_domains`.

### 3

Все пункты сразу:

- специализация кандидата равна специализации потребности;
- дистанция грейда не больше 1;
- есть каждый обязательный навык;
- хотя бы один обязательный навык подтверждён тестом с баллом не ниже 70;
- минимум зарплаты не выше верхней границы вилки (или минимума нет);
- формат совместим;
- домен допустим;
- статус `seeking` или `open`, профиль виден;
- есть след задачи: проект длиннее 80 символов, у которого навыки пересекаются с обязательными или текст называет обязательный навык, либо описание опыта длиннее 80 символов и называет обязательный навык. Имя навыка ищется отдельным словом (Python, Go, Kafka и синонимы из таксономии).

### 2

Все пункты сразу, и это не уровень 3:

- специализация равна или смежная (`taxonomy/data/specializations.yaml`);
- дистанция грейда не больше 1;
- закрыто хотя бы половина обязательных навыков (`число найденных * 2 >= число обязательных`);
- минимум зарплаты не выше `1.3 * salary_to` (или минимума нет);
- статус `seeking` или `open`, профиль виден;
- домен допустим.

### 1

Не уровень 2 и не 3, и при этом есть хотя бы одно: общий обязательный или желательный навык, та же специализация или смежная.

### 0

Ничего из списка выше. Обычно другая, не смежная специализация и ни одного общего навыка с потребностью.

В золотом наборе 10 потребностей × 30 кандидатов. Срез набирается квотами 8/8/7/7 по меткам 3/2/1/0, недостаток добирается из оставшихся. Код: `eval/label.py`.

## Пары для порога sim (50 штук)

`eval/sim_pairs.jsonl`. Метка пары «требование потребности × единица опыта» тоже не смотрит на косинус:

- **3** — одно и то же `family` и есть общий навык;
- **2** — та же специализация и есть общий навык, но семейства разные;
- **1** — та же или смежная специализация, без условий выше;
- **0** — специализация другая и не смежная.

`family` задаётся навыками текста: `kafka` → `stream-kafka`, `pytorch` → `ml-train`, frontend → `frontend-ui`, devops / docker / kubernetes → `devops-cluster`, `postgresql` → `warehouse-sql`, иначе `backend-api`.

Порог в `eval/sim_thresholds.json` растягивает **косинус бинарных токенов**, не эмбеддинг e5:

- `sim_offset = 0.0`
- `sim_scale = 0.32`
- Спирмен sim и метки ≈ 0.58
- средние sim по меткам: 0 → 0.03, 1 → 0.08, 2 → 0.16, 3 → 0.32

Наблюдаемый косинус токенов на этих текстах не выше ~0.32. Пороги ТЗ `0.75 / 0.15` обнулили бы все пары. `embed()` сейчас возвращает нулевой вектор, поэтому в `matching/config.py` пороги не переносятся (`apply_to_config: false`). ### Почему он первый в подборке

`score_pair` ещё заглушка и всем ставит 0.5. Ниже — локальная копия §6 в `seed/generate.py`, только чтобы проверить сценарий. В прод-формулу она не входит.

Фильтр §6.1 и гейт must ≥ 0.3 оставляют на этой потребности **24** кандидата. Из них **9** имеют Kafka с `source=test` (демо и восемь junior/middle/senior с баллом 70; остальные 15 — Kafka только из резюме, покрытие 0.4).

Веса middle, experience fit = 0 (так будет, пока эмбеддинги нулевые):

- must_cov = (98+97+96)/300 = 0.97
- grade_fit = 1
- ef = 0
- skill_avg = 0.97
- fsp = 1
- fresh = 1
- E = 0.30·0.97 + 0.20·1 + 0.15·0.97 + 0.05 + 0.05 = **0.7365**
- C = 1 (вилка, remote, все навыки потребности в «интересных», fintech в любимых доменах, три бенефита, два этапа)
- открытых приглашений нет, S = **0.7365**

Соседи по пулу слабее: Kafka-тест не выше 70, Go и PostgreSQL только из резюме (0.4), ФСП нет, активность на 45 дней старше. При равном ef=0 демо на **1 месте**. Тот же ранг, если sim заменить косинусом токенов: в его единицы опыта вставлены формулировки требований дословно, у остальных — внутренние заявки без антифрода.

Подсказка «Kafka только подтверждённая»: **24 → 9**. Средний S при ef=0: **0.2957 → 0.3918**.

Когда агент D включит e5, у демо остаётся запас: тексты требований лежат внутри его проекта, опыта и достижения ФСП (trust 1.0, роль owner), а не только в общем упоминании Kafka.
